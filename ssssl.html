URL + name │ POST /api/scan ▼ worker thread ──รัน 9 tools แบบขนาน──▶ probe · nmap · nikto · nuclei · curl │ gobuster · redis-cli · smbclient · snmpwalk │ (สตรีม log สดผ่าน SSE ไปที่ UI) ▼ target dict (ผลสแกนรวม: title/server/port/nuclei_findings/nikto…) │ ▼ rank.rank_target() ──ให้คะแนน 27 ตระกูล──▶ ranking │ ▼ faraday_model.normalize_target() ──จัด report──▶ host / services / vulnerabilities / attack_order │ ├──▶ บันทึก data/scans/<id>.json (history) └──▶ /result → แสดง Dashboard เต็มหน้า

Ranking ทำงานยังไง

27 families (flask, tomcat, redis, drupal, nginx, …) │ แต่ละตระกูล → candidate_features() = 7 ฟีเจอร์ ▼ มี models/model.json ? ├─ มี → standardize features → sigmoid(intercept + coef·X) → probability └─ ไม่มี → softmax ของ heuristic_score (fallback) ▼ sort ด้วย probability → ranking (27 rows) ▼ attack_order เรียง: Confirmed < Reported < Open < Ranked → severity → confidence
หลักการสำคัญ: Confirmed จาก nuclei/nikto (เจอ CVE จริง) ขึ้นก่อน เสมอ ตามด้วย speculative จาก model — AI อ่าน report แล้วยิงตามลำดับนี้

ฟีเจอร์ (Feature) ต่อ 1 ตระกูล

ฟีเจอร์ คำนวณยังไง
title_alias_score ชื่อตระกูลมีใน <title> ของหน้าไหม
server_alias_score มีใน Server: / X-Powered-By: header
nmap_alias_score มีใน banner / service line จาก nmap
body_alias_score มีใน HTTP status / body
port_score port ตรงกับ port ปกติของตระกูล (redis=6379)
protocol_score HTTP หรือ non-HTTP ตรงกับธรรมชาติของตระกูล
http_tool_score ความลึกของการสแกน HTTP (probe/nikto/wapiti)

Heuristic score

heuristic = 2.5·title + 2.0·server + 2.0·nmap + 1.2·body
           + 0.7·port + 0.6·protocol + http_tool
⚠ Label leakage: ห้ามใช้ชื่อ target / ชื่อตระกูล / CVE เป็นฟีเจอร์ — ไม่งั้น model จำ "เลข" แทนการเรียนรู้ช่องโหว่จริง

การเทรน (Logistic Regression)

ข้อจำกัด + ทางไปต่อ

ข้อจำกัด · model ปัจจุบันเทรนจากข้อมูล vulhub (weak label) → target ที่ไม่ใช่ vulhub (เช่น Flask port 8080) ranking อาจไม่ติด top
ทางไปต่อ — validation loop (active learning):
1
ยิง exploit จริงกับ candidate ที่จัดอันดับไว้
2
บันทึกผล success / fail (0/1) ลง dataset
3
retrain model ด้วย ground-truth จริง
4
ยิ่งสแกนมาก ยิ่งมี label จริง → ranking ยิ่งแม่น
ต่อ MCP / AI ได้เลย: อ่าน /api/scan/<id>/report (JSON schema 1.0) → วน attack_order → แต่ละ item มี command + method ให้รันยืนยันต่อได้
